Getting Started

Quiet User Interface Skills gives developers and AI coding agents a calm, zero-dependency front-end toolkit. Instead of fighting cluttered dashboards, unreadable dark themes, or hand-coded SVG coordinates, you work from one shared design contract that compiles clean interfaces and exact charts out of the box.

What Quiet User Interface Skills Solves

  • Calm screens without clutter: Pages follow clear reading widths, balanced spacing, and predictable navigation across phones, desktops, wall displays, and control consoles.
  • Honest 1-2-5 charts: Quantitative plots snap to clean 1, 2, and 5 axis steps, label units and uncertainty ranges plainly, and show missing-data gaps honestly instead of smoothing over them.
  • Automatic 4-theme contrast: One CSS token stylesheet (tokens/quiet-ui-tokens.css) switches smoothly across Pure White, Warm Paper, Dark, and Dark Paper while meeting contrast standards without !important.
  • Built-in HTML and CSS verification: An offline Python auditor inspects your generated pages and stylesheets for clipped labels, low contrast, unlabeled form fields, and style drift before you ship.
Note

Core engine modules (skills/, src/, scripts/, tests/) are licensed under Apache 2.0. Design tokens, starter kits in customizations/, and every page or chart you generate are MIT-licensed with zero attribution requirements.

Install in One Command

Clone the repository and run the installer to register both the native Antigravity plugin and portable cross-agent skills (Claude Code, Cursor, Codex, and Windsurf):

bash
git clone https://github.com/FrankXLT/quiet-ui-skills.git
cd quiet-ui-skills
./install.sh

Running ./install.sh installs the plugin bundle to ~/.gemini/config/plugins/quiet-ui-skills/ and copies the three portable skills into ~/.agents/skills/{quiet-ui,quiet-evidence,quiet-bridge}/.

If you prefer installing individual pillars through the Skills CLI, pick the ones you need:

bash
npx skills add https://github.com/FrankXLT/quiet-ui-skills --skill quiet-ui
npx skills add https://github.com/FrankXLT/quiet-ui-skills --skill quiet-evidence
npx skills add https://github.com/FrankXLT/quiet-ui-skills --skill quiet-bridge

Your First Figure or Page in Under 2 Minutes

You can try Quiet UI immediately using pure Python (>= 3.10) with zero third-party packages.

1. Compile a Calibrated Chart

Compile one of the included evidence specs into a standalone, 4-theme HTML5 page:

bash
python3 -B skills/quiet-evidence/scripts/compile_evidence.py \
  content/corpora/02-cloud-cyber-and-ai-ops/evidence/v06_ai_calibration_plot.json \
  --rigor L2 --theme white --out first-chart.html

Swap --fragment in place of --out when you want an embeddable HTML/SVG fragment to drop directly into an existing app or Markdown guide.

2. Build a Calm Page with Design Tokens

Link tokens/quiet-ui-tokens.css (and optionally skills/quiet-evidence/assets/quiet-evidence-bundle.css) inside your HTML <head>, then set data-theme="white" on <html>:

html
<!doctype html>
<html lang="en" data-theme="white">
<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />
  <title>Service Health Summary</title>
  <link rel="stylesheet" href="./tokens/quiet-ui-tokens.css" />
  <style>
    body {
      margin: 0;
      padding: 2rem;
      background: var(--bg-canvas);
      color: var(--text-primary);
      font-family: var(--font-sans);
    }
    .summary-card {
      max-inline-size: 46rem;
      padding: 1.5rem;
      background: var(--bg-surface);
      border: 1px solid var(--border-hairline);
      border-radius: var(--radius-card);
    }
  </style>
</head>
<body>
  <main class="summary-card">
    <h1>API Gateway Readiness</h1>
    <p>All regional probes remain within target response tolerances.</p>
  </main>
</body>
</html>

3. Verify Layout, Contrast, and Drift

Run the portable auditor against your generated HTML file to catch contrast issues, clipped SVGs, unlabeled controls, or style drift:

bash
python3 -B skills/quiet-ui/scripts/audit_quiet_html.py first-chart.html --strict-drift

When working inside an ongoing codebase, initialize a .quiet-ui.md context file once so agents remember your layout mode and blocklist rules across sessions:

bash
python3 -B skills/quiet-ui/scripts/audit_quiet_html.py --init-context .quiet-ui.md

4. Preview Locally

Serve the local studio and documentation portal on port 8788:

bash
python3 -B scripts/serve_showcase.py --port 8788

60-Second Brand Customization

You do not need to edit core skill files or hand-tune twenty separate stylesheets to match your product palette. Quiet UI drives both interface shells and compiled charts from a single manifest so your brand stays consistent everywhere.

One Manifest for Shells and Charts

Every customization lives in its own folder under customizations/<my-brand>/ with a customization.json manifest and a styles/overrides.css file:

  • UI shells read your tokens for page canvases, card surfaces, text ink, buttons, corner radius, and density.
  • Compiled SVG and ECharts figures read the same palette so axis highlights, focal series, and status badges match the surrounding page automatically across all four surface themes (white, paper, dark-paper, and dark).
Important

Treat skills/, tokens/, customizations/brand-starter/, and customizations/personal-starter/ as read-only blueprints. Always copy a starter into a new folder such as customizations/acme-app/ before editing.

Option B: Manual CLI Workflow

To customize a product or workspace showcase directly from the terminal:

  1. Clone a starter into your own folder:
bash
cp -r customizations/brand-starter customizations/my-brand
  1. Edit customizations/my-brand/customization.json: Update name, title, palette hexes, fonts, corner_geometry (auto, sharp, subtle, rounded, soft), and density.
  2. Override tokens cleanly in CSS: Wrap palette and typography changes inside @layer tokens inside customizations/my-brand/styles/overrides.css so they sit neatly in the cascade (@layer reset, tokens, shell, archetypes, evidence, views, utilities;) with zero !important rules:
css
@layer tokens {
  :root {
    --accent-primary: #1D4ED8;
    --accent-focal: #0F766E;
    --font-sans: 'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif;
    --font-mono: 'JetBrains Mono', 'Fira Code', ui-monospace, monospace;
  }

  :root[data-theme="white"] {
    --bg-canvas: #F8FAFC;
    --bg-surface: #FFFFFF;
    --text-primary: #0F172A;
    --text-secondary: #334155;
  }

  :root:is([data-theme="dark"], [data-theme="dark-paper"]) {
    --accent-primary: #60A5FA;
    --accent-focal: #2DD4BF;
    --bg-canvas: #090D16;
    --bg-surface: #0F1624;
    --text-primary: #F1F5F9;
    --text-secondary: #CBD5E1;
  }
}
  1. Compile and verify your customized showcase:
bash
python3 -B customizations/scripts/build_showcase.py customizations/my-brand
python3 -B customizations/scripts/verify_customization.py customizations/my-brand --check-immutability

The verifier checks WCAG text-to-surface contrast ratios (>= 4.5:1), confirms zero !important overrides, and verifies that none of the read-only starter or skill directories were modified.

Building a 3-Route Public Project Site

If you want a clean project website (Overview, Docs, and an optional Demo tab) rather than a showcase explorer, start from customizations/project-site-starter/:

bash

Update site/oaw-site.json with your project metadata, Markdown guide list (docs_reader.sources), and install commands, then compile the static site:

Architecture & Three Pillars

Quiet UI separates how a screen looks, how numbers are plotted, and how the message is written into three focused skills—quiet-ui, quiet-evidence, and quiet-bridge. Instead of asking an AI coding agent or developer to juggle layout physics, SVG coordinate math, and executive framing in one giant prompt, each pillar owns one clear job.

Note

You do not need to learn every technical rule up front. Start with plain goals—readable text, honest numbers, and a layout tailored to the reader—and let each pillar supply the exact building blocks.

Plain-Language Overview of the Three Pillars

1. quiet-ui — Surfaces, Shells, and Physical Readability

Think of quiet-ui as the room and furniture of your interface. Whether someone is reading a printed handout, tapping a hospital bedside screen, or inspecting a desktop workbench, the surface automatically adapts:

  • 7 delivery mediums (M1–M7): Tuned rules for paper and print (M1), editorial web articles (M2), stateful desktop/mobile web apps (M3), walk-up point-of-interest kiosks (M4), 10-foot ambient wall displays (M5), collimated optical HUDs (M6), and transparent window overlays (M7).
  • 5 polymorphic navigation shells (N0–N4): Layouts morph cleanly from a distraction-free document stage (N0), an adaptive left rail (N1), a sticky top bar (N2), or a header-plus-rail command deck (N3), down to a thumb-friendly mobile bottom dock (N4, strictly restricted to viewports under 700px).
  • 4 calibrated themes (white, paper, dark, dark-paper): Built with OKLCH color tokens and a shared --chart-1..5 palette so light, warm-paper, and dark surfaces stay readable without manual color tweaking.
  • Hard 11px legibility floor: No CSS rule or rendered element is allowed to shrink below 11px, and sticky header bars stay compact so content owns the first screen.

2. quiet-evidence — Calibrated Charts and Engineering Diagrams

Think of quiet-evidence as the drafting table. Instead of letting an LLM guess SVG pixel coordinates freehand—which often causes overlapping labels or clipped axes—you describe data or system topology in a structured JSON spec and let a deterministic compiler draw the figure:

  • 6 calibrated modalities: Covers (1) scalar readouts and gauges, (2) tables and matrices, (3) hardware bitfields and registers, (4) analytical and spectral plots, (5) multi-channel waveforms and timing diagrams, and (6) schematics and topologies.
  • Zero freehand SVG guessing: Static specs compile through compile_evidence.py, while live browser charts route through window.QuietSvgLayout and QuietEChartsDefaults so tick intervals, margins, and label clearances stay mathematically consistent.

3. quiet-bridge — Plain-Language Framing Without Changing the Numbers

Think of quiet-bridge as the translator in the room. A plant operator, a systems engineer, and a program manager all look at the same system, yet each needs a different level of detail and speed:

  • 7 audience lenses: Technician & Operator, Discipline Engineer, Project Systems Engineer, Program Manager, Consumer & Common Reader, Educator & Mentor, and Student & Learner.
  • 3 decision tempos: Tactical Seconds (5–15 second anomaly triage), Executive Minutes (1–3 minute gate review), and Analytical Deep Dive (10–45 minute peer-reviewed proof).
  • The Numerical Conservation Law: Presentation may adjust wording and jargon density, never the underlying truth. Sample counts (N), timestamps, units, limits, and baselines must trace back to the same verified data source across web briefs, slide decks, and printed handouts.

Calibrated Charts & Layout Auditor

Most chart bugs happen when code draws raw pixels by hand or hides missing measurements behind smooth curves. Quiet UI solves both problems in two steps: compile charts from structured JSON specs so math and labels stay exact, then run an automated layout auditor to catch visual and accessibility regressions before shipping.

Why Quiet UI Compiles Charts from JSON Specs

Writing <svg> coordinates manually in an editor or asking an AI model to guess x/y numbers leads to clipped text, awkward tick marks, and misleading trends. Describing a figure in urn:quiet-ui:schema:v9:<modality> JSON gives every chart five built-in guarantees:

  • 1-2-5 steps: Axes snap to clean human-readable intervals (1, 2, 5 times powers of 10) rather than irregular fractions like 3.7 or 14.3, making mental estimation effortless.
  • Explicit unit labels: Every axis and readout pairs the quantity with its unit (for example, Active Power, P / kW or η_bte / %) so readers never guess whether a value is watts, kilowatts, or percent.
  • Honest gaps: Missing or null samples stay visible as broken gaps in lines and waveforms instead of being silently bridged by fake interpolation.
  • Chart | Table toggle: Takeaway figure cards pair the visual chart with a clean data table so screen readers, keyboard users, and detail checkers can inspect exact numbers.
  • Copy data and Copy for AI: One click exports tab-separated values (TSV) for spreadsheets (Copy data) or a structured Markdown summary (Copy for AI) ready to paste into an analysis prompt.

How audit_quiet_html.py Protects Every Page

skills/quiet-ui/scripts/audit_quiet_html.py is a portable quality gate you can run against a single file, a static build directory, or a live local server. Think of it as an automated design and accessibility reviewer with three layers:

  1. Static HTML, CSS, JS & JSON checks: Scans source files immediately—with no browser needed—to catch CSS overrides (!important), tiny hardcoded fonts (< 11px), missing form labels, dead-end empty states, chrome emojis, and inline mock fixtures.
  2. Token discipline (--strict-drift): Flags raw #hex, rgb(), and hsl() colors in application CSS or inline presentation styles so pages use semantic var(--*) tokens instead of drifting off-theme.
  3. Persistent .quiet-ui.md project contract: Run --init-context once to create .quiet-ui.md in your repo root (or pass --context). It remembers Greenfield vs. Brownfield mode, mount prefixes, file exclusions, --strict-drift, and your Deprecation Blocklist (selector: / copy:) so removed legacy UI never creeps back in.
  4. Live browser checks (--cdp): Launches Headless Chrome (requires selenium + Chrome) at 390px (phone), 820px (unfolded foldable / tablet), and 1440px (desktop) to measure real rendered pixel bounds—catching oversized sticky headers, clipped controls, and SVG labels colliding with plotted lines.
bash
# 1. Create starter .quiet-ui.md contract (auto-discovered by future runs)
python3 -B skills/quiet-ui/scripts/audit_quiet_html.py --init-context path/to/repo/.quiet-ui.md

# 2. Run static + strict token-drift checks
python3 -B skills/quiet-ui/scripts/audit_quiet_html.py path/to/web --context path/to/repo/.quiet-ui.md --strict-drift

# 3. Run live Headless Chrome sweep at 390px, 820px, and 1440px
python3 -B skills/quiet-ui/scripts/audit_quiet_html.py http://127.0.0.1:8788/ --cdp --mount-prefix /web=/path/to/web

Reusable OAW Project-Site Shell (WF-10)

Instead of maintaining a heavy JavaScript framework for repository websites, WF-10 builds a fast, zero-dependency static site from customizations/project-site-starter/ and customizations/scripts/build_project_site.py.

The Three-Route Pattern

  1. Overview (index.html at root): Presents the project headline, copy-ready install commands, plain-language feature blocks, optional domain preview cards, and compiled architecture diagrams beneath a single 46px top bar shared across routes.
  2. Demo (demo/index.html, optional): Wraps an interactive studio or app entry inside a subfolder with the same single-bar 46px top bar (Overview, Demo, and Docs navigation) and preserves query parameters such as mode, view, world, and domain. Set routes.demo.enabled and demo_wrapper.enabled to false for docs-only repositories.
  3. Docs (docs/index.html): Renders repository Markdown files into a responsive reader. Desktop screens (>= 960px) show a sticky table-of-contents sidebar beside the guide text, while smaller screens (< 960px) add a compact 38px Chapters bar (#oaw-docs-subbar, sticky below 680px and static from 680px to 959px) displaying the active chapter title and opening a light-dismiss mobile outline drawer (<dialog closedby="any">).

Unified Top Bar, Ctrl+K Search & Theme Sync

  • Clean Projects menu & responsive route pill: The left side pairs OAW Projects with a clean Projects popover (All Projects on Row 1 above sibling project links, with zero underlines) and Overview, Demo, and Docs underline tabs on wider screens (>= 900px). Below 900px, those tabs fold into a compact 32px route pill (#oaw-route-btn) so Overview and Demo always remain a single 46px bar.
  • Ctrl+K Search modal (This Space & All OAW): Clicking the top-bar Search button (a 32x32 icon button below 960px) or pressing Ctrl+K (Cmd+K on macOS) opens a modal search dialog (#oaw-search-dialog). Nothing is added to the page or fetched over the network until you open it. Searches default to This Space (the site's search-index.json) and can switch to All OAW to combine results across OAW spaces.
  • 9-dot ecosystem switcher & 4-theme sync: The 9-dot menu links Home, Learn (Open Preview), Projects (Active), and the live Research workspace (https://research.oaworkbench.org/, Preview). Beside it, the @<owner> menu lets visitors choose from 4 themes (Pure White, Warm Paper, Dark, Dark Paper) and keeps oaw_theme_v99, quiet-ui-site-theme, and ?theme= synchronized across every route and the interactive demo.

Markdown Diagram Fences, Search Index & Social Previews

  • Inline quiet-evidence diagram fences: Wrap any urn:quiet-ui:schema:v9:* JSON spec inside a ```quiet-evidence (or ```json-diagram) fenced block in your Markdown guide. The compiler turns it into a crisp, theme-safe inline <svg> diagram at build time with zero client-side JavaScript.
  • Static search-index.json (OAW 1.5.0) & zero-results recovery: Every build writes a deterministic <site_root>/search-index.json (version, updated_at, pillar: "projects", entries) covering Overview, Demo, and Docs sections for the Ctrl+K modal. On /docs/, an inline #oaw-docs-search-index payload also powers instant guide filtering (/ shortcut) with a recovery button (#oaw-empty-clear-btn) and quick jumps if nothing matches.
  • 1280x640 SVG & PNG social previews: Every build writes a crisp 1280x640 SVG preview card beside social_preview.image_path by default (--no-social-svg to skip), and passing --social-png renders the matching PNG card using Pillow only when requested.

# Copy the MIT starter kit and customize oaw-site.json + docs/*.md
cp -r customizations/project-site-starter my-project-site

# Build Overview, Docs, optional Demo, and 1280x640 SVG + PNG social previews
python3 -B customizations/scripts/build_project_site.py \
  --config my-project-site/oaw-site.json --out dist/ --social-png

Add --bundle to inline quiet-ui-tokens.css and optional styles/overrides.css directly into the generated HTML pages for single-file portability.
