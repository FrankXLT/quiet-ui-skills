Getting Started with the OAW Project Site Shell

The OAW Project Site Shell gives an open-source repository a clean, fast documentation and showcase website with zero runtime build dependencies. You write plain Markdown guides, describe your project in oaw-site.json, and compile static HTML ready for GitHub Pages or any static host.

1. Copy the Starter into Your Repository

Copy customizations/project-site-starter into your project repository (for example, into a site/ folder) so your team owns every configuration file, guide, and stylesheet directly.

text
site/
├── oaw-site.json           # Site metadata, routes, hub links, and doc list
├── docs/
│   ├── getting-started.md  # Maintainer onboarding guide
│   └── architecture.md     # Three-route layout and pipeline diagram
└── styles/
    └── overrides.css       # Optional brand palette and font overrides

2. Configure oaw-site.json

Open oaw-site.json and update the project title, tagline, repository URL, and documentation list. Every path in the manifest must stay relative to the folder containing oaw-site.json.

SectionPurposeKey Fields
projectCore identity and linksslug, title, tagline, version, repo_url, site_url
hubSibling-project switcher menulabel, hub_url, projects (title, url, current)
routesLabels and paths for the three routesoverview, demo (enabled), docs
overviewHero copy, install steps, and previewskicker, headline, summary, primary_cta, install_commands
docs_readerGuides shown in the /docs/ readertitle, subtitle, sources (path, id, title), quick_jumps
demo_wrapperOptional interactive app at /demo/enabled, entry_path, docs_base, topbar_links
social_previewOpen Graph card metadataimage_path, eyebrow, title, subtitle, accent_hex

3. Add Markdown Guides

Place new .md files inside docs/ and register each one in docs_reader.sources inside oaw-site.json:

json
{
  "docs_reader": {
    "title": "Project Guides",
    "sources": [
      { "path": "docs/getting-started.md", "id": "getting-started", "title": "Getting Started" },
      { "path": "docs/architecture.md", "id": "architecture", "title": "Architecture" }
    ]
  }
}

You can use standard GitHub-style headings, tables, [!NOTE] / [!TIP] callouts, and inline quiet-evidence diagram blocks inside any guide.

Tip

Keep all guide links relative (such as ./architecture.md), and avoid workstation filesystem paths or internal network addresses in oaw-site.json. The config validator blocks private network tokens automatically so public builds stay clean.

4. Override Colors and Fonts in styles/overrides.css

Edit styles/overrides.css to adapt the palette and font stack while keeping light and dark themes readable. Use the built-in Quiet UI custom properties so contrast stays consistent across every route:

css
@layer reset, tokens, shell, archetypes, evidence, views, utilities;

@layer tokens {
  :root,
  [data-theme="white"] {
    --accent-primary: #1D4ED8;
    --accent-focal: #0F766E;
    --text-on-accent: #FFFFFF;
    --font-sans: 'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif;
    --font-mono: 'JetBrains Mono', 'Fira Code', ui-monospace, monospace;
  }

  [data-theme="paper"] {
    --accent-primary: #1E40AF;
    --accent-focal: #115E59;
    --text-on-accent: #FFFFFF;
  }

  :is([data-theme="dark"], [data-theme="dark-paper"]) {
    --accent-primary: #60A5FA;
    --accent-focal: #2DD4BF;
    --text-on-accent: #0F172A;
  }
}

5. Build the Static Site

Run build_project_site.py against your site directory to validate oaw-site.json, compile your Markdown guides and diagrams, and generate the output bundle:

bash
python3 -B customizations/scripts/build_project_site.py --config oaw-site.json --out dist/

Once the build completes, open dist/index.html locally or publish dist/ to static hosting. To understand how the three generated routes fit together, read the architecture guide.

Project Site Shell Architecture

The OAW Project Site Shell separates marketing overview, live interactive demos, and long-form documentation into three focused routes. Splitting these jobs keeps the landing page calm, gives interactive tools full viewport room, and turns Markdown guides into a fast, searchable reader.

Three-Route Layout

RoutePurposeKey Chrome & Behavior
/ (Overview)Introduce the project in plain languageSticky topbar, hero summary, copyable install commands, domain previews, and architecture visuals
/demo/ (Interactive Demo)Host an existing HTML app or studioSlim 32 px return bar above the app entry (demo_wrapper.entry_path) with quick links back to Overview and Docs
/docs/ (Searchable Reader)Read and search technical guidesSticky left navigation rail on desktop, responsive table-of-contents sheet on mobile, instant search, and compiled diagrams

/ Overview

The root route (index.html) answers three questions in seconds: what the tool does, how to install it, and where to try or read more. Content comes from the overview section of oaw-site.json, paired with optional social preview metadata (social_preview) for clean link cards.

/demo/ Interactive Demo

When demo_wrapper.enabled is true, the builder wraps your standalone demo page (demo_wrapper.entry_path) inside /demo/. Instead of stacking a heavy navigation header on top of a dense workspace, the wrapper renders a slim 32 px return strip at the top so users can jump back to / or /docs/ without losing canvas height.

/docs/ Searchable Reader

Every Markdown file listed under docs_reader.sources compiles into the /docs/ reader. On wide screens, a sticky sidebar lists documents and section headings; on narrow screens, a touch-friendly drawer opens the same outline. Client-side search filters headings and passages without a backend server, and fenced quiet-evidence blocks compile directly into theme-aware inline SVG schematics.

Shared Shell Chrome

All three routes share the unified design token layer and a compact 46px top bar:

  • Two-Stage Project Switcher: Displays your project's spelled-out name beside OAW Projects, with All Projects pinned at the top above sibling project links.
  • Top-Right Ecosystem & Color Switcher: Pairs the 9-dot Open Agentic Workbench switcher (Home, Learn, Projects, Research) with the maintainer menu holding Pure White, Warm Paper, Dark, and Dark Paper color themes.
  • Keyboard & Touch Ergonomics: Uses skip links, visible focus rings, and 44 px minimum touch targets on mobile viewports.
